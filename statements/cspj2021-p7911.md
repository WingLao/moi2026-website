## Description · 題目說明

:::zh
TCP/IP 協議是網路通訊領域的一項重要協議。今天你的任務，就是嘗試利用這個協議，還原一個簡化後的網路連線場景。

在本問題中，計算機分為兩大類：服務機（`Server`）和客戶機（`Client`）。服務機負責建立連線，客戶機負責加入連線。

需要進行網路連線的計算機共有 $n$ 臺，編號為 $1 \sim n$，這些機器將按編號遞增的順序，依次發起一條建立連線或加入連線的操作。

每臺機器在嘗試建立或加入連線時需要提供一個地址串。服務機提供的地址串表示它嘗試建立連線的地址，客戶機提供的地址串表示它嘗試加入連線的地址。

一個符合規範的地址串應當具有以下特徵：

1. 必須形如 `a.b.c.d:e` 的格式，其中 $a, b, c, d, e$ 均為非負整數；
2. $0 \le a, b, c, d \le 255$，$0 \le e \le 65535$；
3. $a, b, c, d, e$ 均不能含有多餘的前導 $0$。

相應地，不符合規範的地址串可能具有以下特徵：

1. 不是形如 `a.b.c.d:e` 格式的字串，例如含有多於 $3$ 個字元 `.` 或多於 $1$ 個字元 `:` 等情況；
2. 整數 $a, b, c, d, e$ 中某一個或多個超出上述範圍；
3. 整數 $a, b, c, d, e$ 中某一個或多個含有多餘的前導 $0$。

例如，地址串 `192.168.0.255:80` 是符合規範的，但 `192.168.0.999:80`、`192.168.00.1:10`、`192.168.0.1:088`、`192:168:0:1.233` 均是不符合規範的。

如果服務機或客戶機在發起操作時提供的地址串不符合規範，這條操作將被直接忽略。

在本問題中，我們假定凡是符合上述規範的地址串均可參與正常的連線，你無需考慮每個地址串的實際意義。

由於網路阻塞等原因，不允許兩臺服務機使用相同的地址串，如果此類現象發生，後一臺嘗試建立連線的服務機將會無法成功建立連線；除此之外，凡是提供符合規範的地址串的服務機均可成功建立連線。

如果某臺提供符合規範的地址的客戶機在嘗試加入連線時，與先前某臺已經成功建立連線的服務機提供的地址串相同，這臺客戶機就可以成功加入連線，並稱其連線到這臺服務機；如果找不到這樣的服務機，則認為這臺客戶機無法成功加入連線。

請注意，儘管不允許兩臺不同的服務機使用相同的地址串，但多臺客戶機使用同樣的地址串，以及同一臺服務機同時被多臺客戶機連線的情況是被允許的。

你的任務很簡單：在給出每臺計算機的型別以及地址串之後，判斷這臺計算機的連線情況。
:::

## Input · 輸入格式

:::zh
第一行，一個正整數 $n$。

接下來 $n$ 行，每行兩個字串 $\mathit{op}, \mathit{ad}$，按照編號從小到大給出每臺計算機的型別及地址串。

其中 $\mathit{op}$ 保證為字串 `Server` 或 `Client` 之一，$\mathit{ad}$ 為一個長度不超過 $25$ 的，僅由數字、字元 `.` 和字元 `:` 組成的非空字串。

每行的兩個字串之間用恰好一個空格分隔開，每行的末尾沒有多餘的空格。
:::

## Output · 輸出格式

:::zh
輸出共 $n$ 行，每行一個正整數或字串表示第 $i$ 臺計算機的連線狀態。其中：

如果第 $i$ 臺計算機為服務機，則：

1. 如果其提供符合規範的地址串且成功建立連線，輸出字串 `OK`。
2. 如果其提供符合規範的地址串，但由於先前有相同地址串的服務機而無法成功建立連線，輸出字串 `FAIL`。
3. 如果其提供的地址串不是符合規範的地址串，輸出字串 `ERR`。

如果第 $i$ 臺計算機為客戶機，則：

1. 如果其提供符合規範的地址串且成功加入連線，輸出一個正整數表示這臺客戶機連線到的服務機的編號。
2. 如果其提供符合規範的地址串，但無法成功加入連線時，輸出字串 `FAIL`。
3. 如果其提供的地址串不是符合規範的地址串，輸出字串 `ERR`。
:::

## Notes and Constraints · 說明與數據範圍

:::zh
**【樣例解釋 #1】**

計算機 $1$ 為服務機，提供符合規範的地址串 `192.168.1.1:8080`，成功建立連線；

計算機 $2$ 為服務機，提供與計算機 $1$ 相同的地址串，未能成功建立連線；

計算機 $3$ 為客戶機，提供符合規範的地址串 `192.168.1.1:8080`，成功加入連線，並連線到服務機 $1$；

計算機 $4$ 為客戶機，提供符合規範的地址串 `192.168.1.1:80`，找不到服務機與其連線；

計算機 $5$ 為客戶機，提供的地址串 `192.168.1.1:99999` 不符合規範。

**【資料範圍】**

| 測試點編號 | $n \le$ | 特殊性質 |
|:-:|:-:|:-:|
| $1$ | $10$ | 性質 1 2 3 |
| $2 \sim 3$ | $100$ | 性質 1 2 3 |
| $4 \sim 5$ | $1000$ | 性質 1 2 3 |
| $6 \sim 8$ | $1000$ | 性質 1 2 |
| $9 \sim 11$ | $1000$ | 性質 1 |
| $12 \sim 13$ | $1000$ | 性質 2 |
| $14 \sim 15$ | $1000$ | 性質 4 |
| $16 \sim 17$ | $1000$ | 性質 5 |
| $18 \sim 20$ | $1000$ | 無特殊性質 |

“性質 1”為：保證所有的地址串均符合規範；  
“性質 2”為：保證對於任意兩臺不同的計算機，如果它們同為服務機或者同為客戶機，則它們提供的地址串一定不同；  
“性質 3”為：保證任意一臺服務機的編號都小於所有的客戶機；  
“性質 4”為：保證所有的地址串均形如 `a.b.c.d:e` 的格式，其中 $a, b, c, d, e$ 均為不超過 ${10}^9$ 且不含有多餘前導 $0$ 的非負整數；  
“性質 5”為：保證所有的地址串均形如 `a.b.c.d:e` 的格式，其中 $a, b, c, d, e$ 均為只含有數字的非空字串。

對於 $100 \%$ 的資料，保證 $1 \le n \le 1000$。
