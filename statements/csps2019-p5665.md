## Description · 題目說明

:::en
A sample has $n$ test cases numbered $1 \sim n$; case $i$ has size $a_i$. Xiao Ming's brute-force program takes time $u^2$ on a case of size $u$, but after running a case of size $u$ it fails on any case of size **smaller** than $u$.

So he splits the cases into segments of **consecutive** indices and merges each segment into one case whose size is the **sum** of its sizes; the merged sizes must be non-decreasing. That is, choose $1 \leq k_1 < k_2 < \cdots < k_p < n$ with

$$ \sum_{i=1}^{k_1} a_i \leq \sum_{i=k_1+1}^{k_2} a_i \leq \cdots \leq \sum_{i=k_p+1}^{n} a_i $$

($p$ may be $0$: everything merged into one case), and **minimise**

$$ \left(\sum_{i=1}^{k_1} a_i\right)^2 + \left(\sum_{i=k_1+1}^{k_2} a_i\right)^2 + \cdots + \left(\sum_{i=k_p+1}^{n} a_i\right)^2 $$

Output the minimum running time.
:::

:::zh
2048 年，第三十屆 CSP 認證的考場上，作為選手的小明開啟了第一題。這個題的樣例有 $n$ 組資料，資料從 $1 \sim n$ 編號，$i$ 號資料的規模為 $a_i$。

小明對該題設計出了一個暴力程式，對於一組規模為 $u$ 的資料，該程式的**執行時間**為 $u^2$。然而這個程式執行完一組規模為 $u$ 的資料之後，它將在任何一組規模**小於** $u$ 的資料上執行錯誤。樣例中的 $a_i$ 不一定遞增，但小明又想在不修改程式的情況下正確執行樣例，於是小明決定使用一種非常原始的解決方案：將所有資料劃分成若干個資料段，段內資料編號**連續**，接著將同一段內的資料合併成新資料，其規模等於段內原資料的**規模之和**，小明將讓新資料的規模能夠遞增。

也就是說，小明需要找到一些分界點 $1 \leq k_1 \lt k_2 \lt \cdots \lt k_p \lt n$，使得

$$ \sum_{i=1}^{k_1} a_i \leq \sum_{i=k_1+1}^{k_2} a_i \leq \cdots \leq \sum_{i=k_p+1}^{n} a_i $$

注意 $p$ 可以為 $0$ 且此時 $k_0 = 0$，也就是小明可以將所有資料合併在一起執行。

小明希望他的程式在正確執行樣例情況下，執行時間也能儘量小，也就是**最小化**：

$$ \left(\sum_{i=1}^{k_1} a_i\right)^2 + \left(\sum_{i=k_1+1}^{k_2} a_i\right)^2 + \cdots + \left(\sum_{i=k_p+1}^{n} a_i\right)^2 $$

小明覺得這個問題非常有趣，並向你請教：給定 $n$ 和 $a_i$，請你求出最優劃分方案下，小明的程式的最小執行時間。
:::

## Input · 輸入格式

:::en
**Because the input is large, in some tests the $a_i$ are generated inside your program.**

Line 1: two integers $n, type$.

1. If $type = 0$: line 2 has the $n$ integers $a_i$.
2. If $type = 1$: line 2 has six integers $x, y, z, b_1, b_2, m$; then $m$ lines with three positive integers $p_i, l_i, r_i$.

Generation for $type = 1$ (tests $23 \sim 25$): for $3 \le i \le n$, $b_i = (x \times b_{i-1} + y \times b_{i-2} + z) \bmod 2^{30}$. It is guaranteed that $p_m = n$ and, with $p_0 = 0$, $p_i < p_{i+1}$. For each $1 \le j \le m$ and each $i$ with $p_{j-1} < i \le p_j$:

$$a_i = \left(b_i \bmod \left( r_j - l_j + 1 \right) \right) + l_j$$

(This only reduces input size; the intended solution does not depend on it.)
:::

:::zh
**由於本題的資料範圍較大，部分測試點的 $a_i$ 將在程式內生成。**

第一行兩個整數 $n, type$。$n$ 的意義見題目描述，$type$ 表示輸入方式。
1. 若 $type = 0$，則該測試點的 $a_i$ **直接給出**。輸入檔案接下來：第二行 $n$ 個以空格分隔的整數 $a_i$，表示每組資料的規模。
2. 若 $type = 1$，則該測試點的 $a_i$ 將**特殊生成**，生成方式見後文。輸入檔案接下來：第二行六個以空格分隔的整數 $x, y, z, b_1, b_2, m$。接下來 $m$ 行中，第 $i (1 \leq i \leq m)$ 行包含三個以空格分隔的正整數 $p_i, l_i, r_i$。

對於 $type = 1$ 的 $23 \sim 25$ 號測試點，$a_i$ 的生成方式如下：

給定整數 $x, y, z, b_1, b_2, m$，以及 $m$ 個三元組 $(p_i, l_i, r_i)$。

保證 $n \geq 2$。若 $n \gt 2$，則 $\forall 3 \leq i \leq n, b_i = (x \times b_{i−1} + y \times b_{i−2} + z) \bmod 2^{30}$。

保證 $1 \leq p_i \leq n, p_m = n$。令 $p_0 = 0$，則 $p_i$ 還滿足 $\forall 0 \leq i \lt m$ 有 $p_i \lt p_{i+1}$。

對於所有 $1 \leq j \leq m$，若下標值 $i (1 \leq i \leq n)$ 滿足 $p_{j−1} \lt i \leq p_j$，則有

$$a_i = \left(b_i \bmod \left( r_j − l_j + 1 \right) \right) + l_j$$

**上述資料生成方式僅是為了減少輸入量大小，標準演算法不依賴於該生成方式。**
:::

## Notes and Constraints · 說明與數據範圍

:::zh
【樣例 1 解釋】

最優的劃分方案為 $\{5,1\}, \{7\}, \{9\}, \{9\}$。由 $5 + 1 \leq 7 \leq 9 \leq 9$ 知該方案合法。

答案為 $(5 + 1)^2 + 7^2 + 9^2 + 9^2 = 247$。

雖然劃分方案 $\{5\}, \{1\}, \{7\}, \{9\}, \{9\}$ 對應的執行時間比 $247$ 小，但它不是一組合法方案，因為 $5 \gt 1$。

雖然劃分方案 $\{5\}, \{1,7\}, \{9\}, \{9\}$ 合法，但該方案對應的執行時間為 $251$，比 $247$ 大。

【樣例 2 解釋】

最優的劃分方案為 $\{5\}, \{6\}, \{7\}, \{7\}, \{4,6,2\}, \{13\}, \{19,9\}$。
